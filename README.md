# Smart Dark PDF Reader

A Chrome extension that shows PDFs in dark mode without inverting their colors.

Plain inversion turns red into cyan and photos into negatives. This viewer renders each page with
[PDF.js](https://github.com/mozilla/pdf.js), then recolors pixels in the OKLab color space: it flips
lightness (paper becomes the dark background, ink becomes light text) and keeps hue and chroma. Photos are
found through PDF.js's image coordinates and left alone; scans and screenshots of text are darkened with the
page. Colored text is lifted until it meets WCAG AA contrast against the background.

## Layout

```
src/
  manifest.json
  background.js          service worker: PDF redirect rules (declarativeNetRequest), one-shot bypass
  viewer/                the PDF viewer page
    smart-invert.js      color mapping, image classification, page recoloring
  popup/                 toolbar popup: on/off, auto-open, theme, image mode
  welcome/               first-run page: permission request, sample PDF
  shared/                settings + shared popup/welcome styles
  icons/, sample/        generated by `npm run assets`
scripts/                 build, package, icons, sample PDF, store screenshots
test/unit/               color-mapping tests (node:test)
test/e2e/                loads the built extension in Chrome with Puppeteer
docs/                    research notes, privacy policy, store listing text
store/                   store screenshots and promo tile
```

## Commands

```sh
npm install
npm run build          # dist/  -> load it at chrome://extensions with "Load unpacked"
npm test               # unit tests
npm run e2e            # end-to-end tests in your installed Chrome
npm run package        # smart-dark-pdf-<version>.zip for the Chrome Web Store
npm run assets         # regenerate icons and the sample PDF
npm run store-assets   # regenerate store screenshots
```

The e2e tests and store screenshots use `dist-e2e/`, a test-only build where site access is granted at
install time because automated browsers cannot click Chrome's permission prompt. Never upload `dist-e2e/`.

## How a PDF reaches the viewer

1. The user grants optional `<all_urls>` access (welcome page or popup).
2. `background.js` registers dynamic `declarativeNetRequest` rules (Chrome 128+) that redirect responses with
   `Content-Type: application/pdf` to `viewer/viewer.html?DNR:<url>`. POST responses and download links are
   left alone. The rule set is adapted from Mozilla's PDF.js extension.
3. The viewer fetches the PDF again with credentials, renders pages lazily, and recolors each one.

"Open in built-in viewer" asks the service worker for a session rule that lets that one URL through, then
removes it after a few seconds.
