# Plan 7: iPhone app as a web app (PWA) (done)

**Research (2026-10-03):** iOS 26 opens any site added to the Home Screen as a web app. Home-screen apps get
their own storage (60% of disk quota) and are not subject to Safari's 7-day storage cap; `storage.persist()`
is requested at start. Ship both manifest icons and an opaque `apple-touch-icon` (some iOS versions ignore
manifest icons). File access is the picker only (no "Open with" for web apps). Saving files uses the share
sheet. Scheduled local notifications are not available to web apps.

**Built:**
- `vite-plugin-pwa` (Workbox 7.4): manifest, offline precache of the whole app including the pdf.js worker,
  character maps, standard fonts and wasm decoders (205 files, ~5.9 MB), `clientsClaim` + `skipWaiting` so
  the first visit is already offline-ready. Not registered inside the desktop app.
- Icons: 192/512 (any), 512 maskable (opaque, safe zone), 180 apple-touch-icon (opaque square).
- iPhone tags: apple-touch-icon, app title, status bar style, theme colors for light and dark.
- In the library on iPhone Safari: a one-time hint "Share → Add to Home Screen".
- Settings: storage used and whether the browser keeps the data permanently.
- Hosting: Vercel (`vercel.json`): build command, output folder, Content Security Policy and other
  security headers, no caching of `sw.js`. GitHub Pages was dropped because the repository is private
  (Pages needs GitHub Pro for private repos). Browser tests run behind the same headers
  (`scripts/serve-app.mjs`).

**Tests:** manifest and icons; service worker control and cache contents on Chromium and WebKit; full
offline run (reload + open a book) on Chromium. Playwright's WebKit puts offline emulation and request
routing in front of service workers, so the offline run itself cannot be automated there; check it once on a
real iPhone (Airplane Mode after the first visit).
